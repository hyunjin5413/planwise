# 소방 도면 AI 검토 서비스 PRD

Nov 7, 2026 @Hyunjin An

도면 이미지를 올리면 소방 관련 법령과 화재안전기준에 맞는지 검토하고, 위반 후보마다 근거 조문과 수정 방법을 안내하는 서비스의 제품 요구사항 문서입니다.

## 개요

**제품 정의.** 도면 이미지를 올리면 소방시설과 피난 요소를 찾아 도면 위에 종류별 색상 박스로 표시하고, 오른쪽 패널에 종류별 개수와 없는 시설, 법령 위반 후보를 근거 조문 및 수정 가이드와 함께 보여주는 검토 보조 서비스입니다.

**해결하려는 문제.**

- 설계 단계의 소방 법규 검토는 소방기술사와 숙련 설계자의 경험에 의존하는 수작업이며, 심볼 개수를 세고 거리를 재는 반복 작업이 큰 비중을 차지합니다.
- 소방서는 건축허가 동의 요구를 받으면 5일(일정 규모 이상은 10일) 안에 회신해야 합니다. 보완 요청이 오가면 인허가 일정 전체가 밀립니다.
- 화재안전기준은 성능기준(NFPC)과 기술기준(NFTC)으로 나뉘어 있고 개정이 잦아, 어느 시점의 기준을 적용해야 하는지 판단하기 어렵습니다.
- 피난 관련 규정이 건축법과 소방법으로 나뉘어 있어 한쪽만 보면 누락이 생깁니다.
- 현장과 인허가에서 오가는 도면은 PDF, 스캔본, 사진이 많습니다. CAD 원본을 전제로 하는 도구는 이 사용자들이 쓸 수 없습니다.

**이미지 입력을 택한 이유.** CAD 원본이 없는 소규모 설계사무소, 건축주, 소방서 담당자, 시공 현장까지 같은 방식으로 쓸 수 있고 도입 장벽이 가장 낮습니다. 대신 축척, 심볼, 실 경계를 이미지에서 복원해야 하므로 인식 품질과 사용자 확인 단계를 핵심 설계 요소로 다룹니다.

배경 조사 자료: Document

## 목표와 성공 지표

**목표.**

1. 도면 이미지에서 소방시설을 찾아 색상 박스로 표시하고 종류별 개수를 자동 집계해, 사람이 심볼을 세고 확인하는 시간을 줄입니다.
2. 설치 의무가 있는데 도면에 없는 시설은 "없음"으로 명시하고, 의무가 없는 시설과 구분해 보여줍니다.
3. 배치 기준 위반 후보를 근거 조문, 적용 시행일, 수정 가이드와 함께 제시합니다.
4. 사용자가 박스와 판정을 바로 고치고 재검토할 수 있게 해, 인식 오류가 최종 결과로 이어지지 않게 합니다.

**비목표 (MVP 기준).**

- 법적 적합 판정이나 인허가 절차의 대체. 최종 판단은 소방기술사와 관할 소방서에 있습니다.
- 성능위주설계 대상 건축물의 화재, 피난 시뮬레이션
- 수리계산서, 펌프 용량 등 계산서 검토
- 소방 도면 자동 작성과 CAD, BIM 원본 편집

**성공 지표.** 목표치는 초안이며 파일럿 데이터로 확정합니다.


| 지표        | 정의                          | MVP 목표(초안)             |
| --------- | --------------------------- | ---------------------- |
| 객체 검출 재현율 | P0 소방 심볼 중 박스로 찾아낸 비율       | 90% 이상                 |
| 객체 검출 정밀도 | 표시한 박스 중 종류까지 맞은 비율         | 85% 이상                 |
| 집계 정확도    | 종류별 개수가 정답과 모두 일치하는 도면 비율   | 80% 이상                 |
| 누락 판정 정확도 | "없음, 설치 필요" 판정이 실제 누락인 비율   | 95% 이상                 |
| 위반 후보 재현율 | 전문가가 찾은 P0 위반 중 서비스가 제시한 비율 | 85% 이상                 |
| 근거 조문 정확도 | 지적 사항에 붙은 조문과 시행일이 맞는 비율    | 98% 이상                 |

| 사용자 수정률   | 결과 박스 중 사용자가 수정, 삭제, 추가한 비율 | 추적 지표 (모델 개선 우선순위에 활용) |


## 타깃 사용자와 사용 시나리오

1차 타깃은 제출 전에 스스로 도면을 점검해야 하는 설계 실무자이고, 소방서는 공공 사업으로 별도 접근하는 2차 타깃입니다.


| 사용자             | 상황                  | 핵심 니즈                             | 우선순위    |
| --------------- | ------------------- | --------------------------------- | ------- |
| 소방설계업체 설계자      | 소방 도면 작성 후 자체 검수    | 심볼 누락, 수평거리와 보행거리 위반을 제출 전에 찾기    | 1차      |
| 건축사사무소 설계자      | 소방 전문인력이 없는 소규모 사무소 | 건축 평면에 필요한 소방시설과 피난 요건을 미리 파악     | 1차      |
| 소방서 건축허가 동의 담당자 | 5일 안에 동의 여부 회신      | 제출 도면의 시설 현황을 빠르게 집계하고 의심 항목부터 확인 | 2차 (공공) |
| 시공사, 감리         | 설계도와 현장 시공의 차이 관리   | 도면 버전 간 시설 개수와 위치 비교              | 3차      |


**시나리오 1. 제출 전 자체 검수.** 소방설계업체 설계자가 5개 층 평면도 PDF를 올립니다. 결과 화면에서 3층 연기감지기가 "없음, 설치 필요"로 표시된 것을 보고, 해당 층 도면에서 감지기 레이어가 출력에서 빠진 것을 발견합니다. 수정본을 다시 올려 지적 사항이 사라진 것을 확인한 뒤 리포트를 내려받아 사내 검토 기록으로 남깁니다.

**시나리오 2. 소규모 사무소의 초기 검토.** 건축사사무소 설계자가 소방설계를 맡기기 전에 계획안 평면 이미지를 올립니다. 건물 정보 확인 화면에서 용도와 층별 면적을 입력하면, 설치해야 하는 소방시설 목록과 현재 도면에 표시된 시설의 차이를 확인하고 협력업체에 요청할 범위를 정리합니다.

**시나리오 3. 동의 회신 전 1차 확인.** 소방서 담당자가 접수된 소방시설 설계도면을 올리고, 오른쪽 패널의 집계표와 지적 사항 목록을 보면서 "위반 의심" 항목부터 원본 도면과 대조합니다.

## 서비스 범위

MVP는 평면도 이미지만으로 판정할 수 있는 항목에 집중하고, 단면 정보나 계산서가 필요한 항목은 이후 단계로 넘깁니다.

**입력 범위.** 층별 평면도 이미지(PNG, JPG, TIFF, PDF 페이지)를 프로젝트당 최대 30장까지 받습니다. 판정은 평면도에만 수행하고, 단면도와 계통도는 업로드는 허용하되 MVP에서는 분류만 합니다.

**대상 건축물 (가정, 미결 사항에서 확정).** 근린생활시설과 업무시설 중심의 중소 규모 건축물로 시작합니다. 용도 수를 좁히면 시행령 별표 4의 판정 규칙과 인식할 심볼 종류가 크게 줄어듭니다. 성능위주설계 대상, 초고층, 지하연계 복합건축물은 제외합니다.

**인식 대상 객체.**


| 분류     | 객체                               | 단계  |
| ------ | -------------------------------- | --- |
| 소화설비   | 소화기, 옥내소화전, 스프링클러 헤드             | P0  |
| 소화설비   | 간이스프링클러 헤드, 자동소화장치, 옥외소화전, 송수구   | P1  |
| 경보설비   | 연기감지기, 열감지기, 발신기, 경종, 시각경보기, 수신기 | P0  |
| 피난구조설비 | 피난구유도등, 통로유도등, 비상조명등             | P0  |
| 피난구조설비 | 피난기구(완강기 등), 유도표지                | P1  |
| 건축 요소  | 실 경계, 실 명칭, 출입문, 계단, 창호          | P0  |
| 건축 요소  | 방화문, 방화셔터, 방화구획선                 | P1  |


**MVP 검토 항목.**

1. 설치 대상 판정: 사용자가 확인한 건물 정보(용도, 층수, 층별 바닥면적, 무창층 여부, 수용인원)로 시행령 별표 4에 따른 설치 의무 시설 목록을 만듭니다.
2. 존재와 집계: 설치 의무 시설별로 도면에서 검출된 개수를 세고, 0개인 시설은 "없음"으로 판정합니다.
3. 실별 설치 여부: 감지기, 스프링클러 헤드가 하나도 없는 실을 찾고 설치 제외 장소에 해당하는지 확인을 요청합니다.
4. 거리 기준: 스프링클러 헤드 수평거리, 소화기 보행거리를 축척 확정 후 계산합니다.
5. 피난 요소: 피난구유도등의 출입구 설치 여부, 직통계단 개수와 이격 거리(건축물의 피난 방화구조 등의 기준에 관한 규칙)를 확인합니다.

**MVP 제외 항목.** 높이와 보 깊이가 필요한 조건(단면도 필요), 계통도 기반 회로와 배관 검토, 수리계산, 제연설비, 방화구획 면적 산정은 Phase 2 이후로 넘깁니다.

## 사용자 흐름

사용자는 업로드 후 축척과 건물 정보 두 가지만 확인하면 결과를 받습니다. 판정에 직접 영향을 주는 값은 반드시 사람이 확인하도록 흐름에 넣었습니다.

1. **프로젝트 생성.** 건물명, 주소(선택), 적용 기준일을 입력합니다. 적용 기준일은 기본값이 오늘이며, 허가 신청일을 지정하면 그 시점에 시행 중인 기준으로 검토합니다.
2. **도면 업로드.** 이미지 여러 장을 한 번에 올립니다. 시스템이 시트 종류(평면도, 단면도, 계통도, 범례)와 층을 자동 분류하고, 해상도가 낮거나 기울어진 이미지는 업로드 단계에서 경고합니다.
3. **축척 확인.** 표제란 축척과 치수선으로 추정한 축척을 보여줍니다. 추정이 불확실하면 사용자가 길이를 아는 두 점을 클릭해 보정합니다.
4. **범례 확인.** 도면에 범례가 있으면 심볼과 객체 종류의 매핑을 제안하고 사용자가 확인합니다.
5. **건물 정보 확인.** 용도, 층수, 층별 바닥면적, 무창층 여부, 내화구조 여부, 수용인원을 자동 추출값으로 채워 보여주고 사용자가 수정합니다. 이 값으로 설치 대상을 판정합니다.
6. **검토 실행.** 층별 진행 상태를 보여주며, 평면도 1장 기준 2분 이내를 목표로 합니다.
7. **결과 확인.** 도면 위에 종류별 색상 박스가 표시되고, 오른쪽 패널에서 종류별 개수, 없는 시설, 지적 사항 목록을 봅니다. 패널 항목을 누르면 도면의 해당 위치로 이동합니다.
8. **수정과 재검토.** 박스를 추가, 삭제하거나 종류를 바꾸면 집계와 판정이 즉시 다시 계산됩니다. 지적 사항마다 확인, 보류, 이의 제기 상태를 남길 수 있습니다.
9. **리포트 내보내기.** 박스가 표시된 도면, 종류별 집계표, 지적 사항과 근거 조문을 PDF로 내려받습니다.

## 기능 요구사항

P0는 MVP 출시에 반드시 필요한 기능, P1은 파일럿 중 추가, P2는 정식 출시 이후 기능입니다.


| ID    | 기능          | 요구사항                                                            | 우선순위 |
| ----- | ----------- | --------------------------------------------------------------- | ---- |
| FR-01 | 이미지 업로드     | PNG, JPG, TIFF, PDF를 여러 장 업로드. PDF는 페이지별 이미지로 변환                | P0   |
| FR-02 | 시트 자동 분류    | 평면도, 단면도, 계통도, 범례를 구분하고 층 번호를 추출. 사용자가 수정 가능                    | P0   |
| FR-03 | 이미지 품질 검사   | 해상도, 기울기, 흐림, 잘림을 검사해 업로드 단계에서 경고                               | P0   |
| FR-04 | 축척 추정과 보정   | 표제란과 치수선으로 축척 추정, 두 점 클릭 보정 기능 제공                               | P0   |
| FR-05 | 범례 인식       | 범례 영역의 심볼을 추출해 객체 종류와 매핑 제안                                     | P1   |
| FR-06 | 실 분할과 실명 인식 | 벽체와 개구부로 실 경계를 복원하고 실 명칭을 OCR로 읽어 용도 매핑                         | P0   |
| FR-07 | 소방 객체 검출    | 인식 대상 객체마다 사각 박스, 종류, 신뢰도를 산출                                   | P0   |
| FR-08 | 건물 정보 확인    | 용도, 층수, 층별 면적, 무창층, 구조, 수용인원을 자동 추출하고 사용자 확인을 받음                | P0   |
| FR-09 | 설치 대상 판정    | 확인된 건물 정보로 시행령 별표 4 기준 설치 의무 시설 목록 생성                           | P0   |

## 이미지 입력 처리 요구사항

| 항목       | 요구사항                                                                      |
| -------- | ------------------------------------------------------------------------- |
| 지원 형식    | PNG, JPG, TIFF, PDF(페이지별 래스터 변환). 파일당 최대 용량과 장수는 인프라 비용 검토 후 확정           |
| 해상도      | 300dpi 이상 권장(A3 출력 기준 긴 변 약 5,000px). 150dpi 미만은 경고하고 거리 판정을 보류           |
| 대형 도면    | A1 이상 대형 이미지는 겹침이 있는 타일로 나눠 추론한 뒤 결과를 병합                                  |
| 사진 촬영 도면 | 원근과 기울기를 보정. 보정 후에도 품질이 낮으면 재업로드 권고                                       |
| 축척       | 표제란 축척 OCR, 치수선 숫자와 픽셀 길이 비교, 그리드 간격을 함께 사용. 추정값 간 차이가 10%를 넘으면 사용자 보정 요청 |
| 거리 판정 조건 | 축척이 확정된 시트에서만 거리 기반 판정을 실행. 미확정이면 해당 항목을 "판정 보류"로 표시                      |
| 범례       | 범례 표를 검출해 회사마다 다른 심볼 모양을 객체 종류에 매핑. 범례가 없으면 표준 심볼 모델로 인식                  |
| 신뢰도      | 객체마다 신뢰도를 산출. 임계값 미만은 점선 박스와 "확인 필요" 상태로 표시하고 집계에는 별도 표기                  |
| 텍스트      | 실 명칭, 치수, 표제란, 범례 문자를 한국어 OCR로 인식. 실 명칭은 용도 사전과 매핑                        |
| 원본 보관    | 업로드 원본과 결과는 암호화 저장. 보관 기간과 삭제 정책은 보안 요구사항에서 정의                            |


**소방 심볼 데이터.** 소방 심볼 전용 공개 데이터셋은 확인되지 않았습니다. AI Hub 건축 도면 데이터(벽, 창호, 공간, 문자 인식)와 FloorPlanCAD로 건축 요소 인식을 사전학습하고, 소방 심볼은 파일럿 고객 도면으로 라벨링 데이터를 구축합니다. 결과 화면의 박스 수정 기능은 그대로 라벨링 도구 역할을 하므로, 사용자 수정 내역을 학습 데이터로 회수합니다.

## 검토 엔진과 가이드 생성

판정은 규칙 엔진이 결정적으로 수행하고, LLM은 법령을 규칙으로 옮기는 작업과 결과를 설명하는 문장에만 씁니다. 같은 도면과 같은 기준일이면 항상 같은 결과가 나와야 하기 때문입니다.

**판정 단계.**

1. **설치 대상 판정 (시행령 별표 4).** 확인된 건물 정보로 층별 설치 의무 시설 목록을 만듭니다.
2. **존재와 집계.** 의무 시설 목록과 검출 결과를 맞춰 시설마다 세 가지 상태 중 하나를 붙입니다.
   - 검출됨: 1개 이상 검출. 개수를 표시합니다.
   - 없음, 설치 필요: 설치 의무가 있는데 0개. 누락 의심 지적 사항을 만듭니다.
   - 없음, 해당 없음: 설치 의무가 없고 0개. 정보로만 표시합니다.
3. **배치 기준 판정 (NFTC).** 실별 설치 여부, 헤드 수평거리, 소화기 보행거리 등 정량 기준을 검사합니다.
4. **피난 요소 판정 (건축 측 규칙).** 직통계단 개수와 이격, 출입구 유도등 설치 여부를 검사합니다.

**판정 유형.** 지적 사항마다 아래 유형 중 하나를 표시해 사용자가 신뢰 수준을 바로 알 수 있게 합니다.


| 유형    | 의미                      | 예시                         |
| ----- | ----------------------- | -------------------------- |
| 위반 의심 | 규칙상 기준 미달이 계산된 경우       | 헤드에서 실 모서리까지 수평거리가 기준 초과   |
| 누락 의심 | 설치 의무 시설이 도면에 없는 경우     | 연기감지기 없음, 설치 필요            |
| 확인 필요 | 해석이 필요하거나 인식 신뢰도가 낮은 경우 | 감지기 없는 실이 설치 제외 장소인지 판단 필요 |
| 판정 보류 | 판정에 필요한 정보가 없는 경우       | 축척 미확정, 단면 정보 필요           |


**규칙 구조.** 규칙 하나는 다음 필드를 가집니다: 규칙 ID, 근거(법령명, 조항, 시행일, 종료일), 적용 조건(용도, 면적, 층), 필요 입력(객체 종류, 축척, 구조 등), 판정 로직, 지적 문구 템플릿, 수정 가이드 템플릿, 관련 질의회신과 유권해석 링크. 규칙은 법령 조문 버전에 묶여 있어 기준일에 따라 다른 규칙이 적용됩니다.

**LLM의 역할.**

- 법령 문장을 규칙 초안으로 변환합니다. 초안은 소방 전문가 승인 후에만 반영합니다.
- 규칙 판정 결과와 조문만을 근거로 지적 사항 설명과 수정 가이드 문장을 만듭니다. 근거에 없는 내용은 생성하지 않도록 검증합니다.
- "확인 필요" 항목에 관련 질의회신과 유권해석을 검색해 요약합니다.

**가이드 문장 예시.** "3층 회의실 북측 모서리에서 가장 가까운 스프링클러 헤드까지 수평거리가 2.8m로, 내화구조 기준 2.3m를 넘습니다. 헤드 1개를 추가하거나 배치 간격을 조정하는 방안을 검토하십시오. 근거: 스프링클러설비의 화재안전기술기준(NFTC 103) 헤드 배치 기준, 기준일 2026-11-07 시행본."

## 검토 결과 화면과 리포트

결과 화면은 왼쪽 도면 위의 색상 박스와 오른쪽 집계 패널로 구성하며, 도면에 없는 시설도 목록에서 빠뜨리지 않고 "없음"으로 표시합니다.

[embed: node/2cc2a901-c69c]

예시에서는 소화기 3개, 스프링클러 헤드 12개(확인 필요 1개 포함), 피난구유도등 1개가 검출되었습니다. 설치 의무가 있는 연기감지기는 0개라 "없음"과 누락 의심으로 강조하고, 의무가 없는 옥외소화전은 "없음, 설치 대상 아님"으로 회색 처리해 구분합니다.

**도면 오버레이.**

- 검출 객체마다 라벨링 도구처럼 사각 박스를 그립니다. 색상은 객체 종류별로 고정하고 패널의 색상 칩과 일치시킵니다.
- 박스 선 모양으로 상태를 구분합니다. 실선은 확정, 점선은 신뢰도가 낮아 확인이 필요한 객체입니다. 지적 사항 위치는 빨간 점선 영역과 번호로 표시합니다.
- 색만으로 구분하지 않도록 박스 옆에 종류 약어(예: 소, SP, 감)를 함께 표시해 색각 이상 사용자도 읽을 수 있게 합니다.
- 박스에 마우스를 올리면 종류, 신뢰도, 관련 지적 사항을 보여주고, 클릭하면 종류 변경과 삭제가 가능합니다. 빈 곳을 드래그하면 새 박스를 추가합니다.
- 층 탭, 확대와 이동, 종류별 표시와 숨김을 지원합니다.

**오른쪽 집계 패널.** 객체 종류별로 색상 칩, 종류명, 개수, 상태를 한 행씩 보여주고 층별과 전체를 전환할 수 있습니다. 행을 누르면 그 종류의 박스만 강조되고 이전과 다음 박스로 순회합니다. 개수가 0인 경우는 아래처럼 나눠 표시합니다.


| 상태        | 조건               | 패널 표시                            |
| --------- | ---------------- | -------------------------------- |
| 검출됨       | 1개 이상 검출         | 개수. 신뢰도 낮은 객체가 있으면 "확인 필요 n개 포함" |
| 없음, 설치 필요 | 설치 의무가 있는데 0개    | "없음"을 강조하고 누락 의심 표시. 지적 사항 자동 생성 |
| 없음, 해당 없음 | 설치 의무가 없고 0개     | "없음, 설치 대상 아님"을 회색으로 표시          |
| 판정 보류     | 인식 품질이나 건물 정보 부족 | "판정 보류"와 사유(예: 축척 미확정)           |


패널 아래쪽에는 지적 사항 목록을 두고 위반 의심, 누락 의심, 확인 필요, 판정 보류 순으로 정렬합니다. 항목을 누르면 도면의 해당 위치로 이동합니다.

**지적 사항 항목.**


| 필드     | 내용                                       |
| ------ | ---------------------------------------- |
| ID와 유형 | 지적 번호, 판정 유형(위반 의심, 누락 의심, 확인 필요, 판정 보류) |
| 위치     | 층, 실 이름, 도면 좌표                           |
| 대상     | 관련 객체 종류와 박스                             |
| 내용     | 무엇이 기준과 다른지, 측정값과 기준값                    |
| 근거     | 법령명, 조항, 적용 시행일                          |
| 수정 가이드 | 권장 조치 문장과 대안                             |
| 참고 자료  | 관련 질의회신, 유권해석 링크                         |
| 신뢰도    | 인식과 판정 신뢰도                               |
| 사용자 조치 | 확인, 보류, 이의 제기와 메모                        |


**PDF 리포트.** 표지(프로젝트, 적용 기준일, 검토 일시), 층별 오버레이 도면, 종류별 집계표("없음" 포함), 지적 사항 목록, 적용 기준 목록 순으로 구성합니다. 모든 페이지에 "검토 보조 결과이며 최종 판단은 자격자와 관할 소방서에 있음" 문구를 넣습니다.

## 법령 지식베이스 관리

기준이 자주 바뀌므로 조문과 규칙을 시행일 기준으로 버전 관리하고, 개정 감지부터 규칙 반영까지를 정해진 절차로 운영합니다.

**수집 대상과 경로.**


| 데이터                          | 경로                                    | 주기       |
| ---------------------------- | ------------------------------------- | -------- |
| 소방시설법, 시행령(별표 2, 4, 5), 시행규칙 | 국가법령정보 공동활용 Open API                  | 매일 변경 확인 |
| NFPC 고시, NFTC 공고             | 국가법령정보 공동활용 행정규칙 API, 소방청과 국립소방연구원 공지 | 매일 변경 확인 |
| 건축물의 피난 방화구조 등의 기준에 관한 규칙    | 국가법령정보 공동활용 Open API                  | 매일 변경 확인 |
| 행정예고(개정안)                    | 국민참여입법센터 행정예고 API                     | 매주       |
| 신구 조문 비교                     | 공공데이터포털 법제처 행정규칙 신구법 비교 API           | 개정 감지 시  |
| 질의회신, 유권해석                   | 법제처 법령해석, 소방 기술민원 공개 자료               | 매월       |


**개정 반영 절차.**

1. 개정 감지: 조문 변경이 확인되면 영향받는 규칙 목록을 자동으로 찾습니다.
2. 초안 생성: 신구 조문 비교를 바탕으로 LLM이 규칙 변경 초안을 만듭니다.
3. 전문가 검토: 소방 자문 인력이 초안을 승인하거나 수정합니다.
4. 회귀 테스트: 기준 도면 세트로 변경 전후 판정 차이를 확인합니다.
5. 배포: 새 규칙에 시행일을 붙여 배포하고, 이전 규칙은 종료일을 붙여 보관합니다.

**운영 원칙.** 행정예고 단계의 개정안은 "예정 기준"으로만 안내하고 판정에는 쓰지 않습니다. NFPC와 NFTC 원문은 HWP로 배포되는 경우가 많아 HWP 파싱 파이프라인을 둡니다. 모든 판정 결과에는 적용한 규칙 버전을 기록해, 나중에 같은 결과를 재현할 수 있게 합니다.

## 시스템 구성

업로드부터 결과까지 7단계로 흐르며, 4단계 사용자 확인을 거친 값만 규칙 엔진에 들어갑니다.

[embed: node/ae3bf91c-6ac8]

결과 화면에서 박스를 고치면 건물 모델이 갱신되고 5단계부터 다시 계산됩니다. 수정 내역은 인식 모델 재학습 데이터로 쌓입니다.

**구현 기반 (안).** AgentOS 위에 구축한다면 건물 모델과 법령 규칙은 Ontology Manager, 법령 수집은 Pipeline Builder, 검토 흐름은 Workflow Builder, 결과 화면은 App Builder로 구성할 수 있습니다. 도면 인식 모델은 별도 추론 서비스로 두고 연동합니다. 구현 기반은 미결 사항에서 확정합니다.
